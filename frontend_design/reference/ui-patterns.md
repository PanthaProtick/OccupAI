# UI Patterns Reference

## Purpose

Use this file when deciding how common interface elements should behave and be structured.

---

# 1. NAVIGATION

Typical desktop:

```text
Logo
Navigation
Secondary action
Primary CTA
```

Typical mobile:

```text
Logo
Menu
```

Navigation should prioritize the most important destinations.

---

# 2. HERO

Typical structure:

```text
Eyebrow
Headline
Description
Primary CTA
Secondary CTA
Visual
```

Hero design should immediately communicate product value.

---

# 3. CARDS

Use cards for meaningful groups.

Good:

```text
Product
Feature
Project
Article
Pricing plan
User
Statistic
```

Avoid wrapping every section inside a card.

---

# 4. TABLES

Use tables for:

* Structured comparison
* Transactions
* Records
* Data-heavy interfaces

On mobile:

```text
Horizontal scroll
Responsive transformation
Priority columns
```

Do not force a desktop table into a tiny viewport.

---

# 5. MODALS

Use for:

* Focused tasks
* Confirmation
* Short forms
* Important information

Avoid using modals for everything.

---

# 6. DRAWERS

Good for:

* Mobile navigation
* Filters
* Secondary controls
* Contextual settings

---

# 7. TABS

Use when content belongs to the same context but has multiple views.

Do not use tabs simply to hide excessive content.

---

# 8. ACCORDIONS

Use for:

* FAQ
* Secondary information
* Optional details

Good when users do not need all content visible simultaneously.

---

# 9. TOOLTIPS

Use for:

* Icon-only controls
* Technical terminology
* Secondary information

Do not hide critical instructions inside tooltips.

---

# 10. SEARCH

For large datasets or content:

```text
Search
+
Filters
+
Sorting
```

Search should be easy to find when it is a primary task.

---

# 11. FORMS

Good form structure:

```text
Label
Input
Help text
Validation
Error
```

Group related fields.

Do not create unnecessarily long forms.

---

# 12. BUTTONS

Hierarchy:

```text
Primary
Secondary
Tertiary
Destructive
```

Do not make all actions primary.

---

# 13. TOASTS

Use for:

* Save confirmation
* Background events
* Short-lived feedback

Do not use toasts for critical information that users may miss.

---

# 14. EMPTY STATES

Use:

```text
Illustration/icon
Title
Explanation
Action
```

Keep the message useful.

---

# 15. LOADING

Choose according to context:

```text
Skeleton → page/content loading
Spinner → short action
Progress → known progress
Optimistic update → immediate feedback
```

---

# 16. ERROR

Good error:

```text
What happened
+
What to do
```

Example:

```text
Couldn't save the project.

Check your connection and try again.

[Try Again]
```

---

# 17. DASHBOARD PATTERN

Typical:

```text
Sidebar
Top bar
Page title
Filters
Key metrics
Main visualization
Secondary data
```

Do not force every dashboard into this exact structure.

---

# 18. LANDING PAGE PATTERN

Possible:

```text
Navbar
Hero
Problem
Solution
Features
Demo
Social proof
Pricing
FAQ
CTA
Footer
```

Adapt to the product.

---

# 19. PORTFOLIO PATTERN

Possible:

```text
Hero
Selected work
Case studies
Experience
Skills
About
Contact
```

Prioritize projects over unnecessary decoration.

---

# 20. E-COMMERCE PATTERN

Possible:

```text
Navigation
Search
Categories
Product grid
Filters
Product page
Cart
Checkout
```

Prioritize shopping flow.

---

# 21. UI CONSISTENCY

Maintain:

```text
Same button language
Same radius
Same spacing
Same icon style
Same typography
Same animation language
```

---

# 22. UX PRINCIPLE

Do not use a UI pattern because it is fashionable.

Use it because it solves the user's problem.
